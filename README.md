# tp123 时区与时间换算工作台

一个本地小工具：把各地时区连同夏令时规则登记进来，再把某一个时刻换算到所有已登记的时区，页面上直接看出各地是当地的几点、谁的日期已经翻到前一天或者后一天、跟来源时区差了几个小时。时区名写得不合规矩、偏移超出范围、夏令时偏移不比标准偏移靠前、开始与结束两段规则写得一模一样、结束年份早于开始年份，保存时当场就会指出来。

有的地区几十年里换过偏移，一条记录装不下这段历史：同一条时区可以**分段登记几个偏移区间**，每段写清开始年份、结束年份与这段期间的偏移。段与段必须首尾相接——一旦出现重叠或者没覆盖到的年份空洞，保存当场被拒绝，并说明是哪两段撞在哪几年、或者哪几年空着。页面上可以按年份查这条时区在某一年实际落在哪一段、用的是哪个偏移；档案详情里能看到完整的分段历史。换算时按输入年份落段取偏移，来源或目标在那一年没有分段覆盖就按不可用处理并写清原因。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5123>

端口固定为 `5123`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 时区档案区列出时区名称、显示名称、当前偏移、是否实行夏令时、夏令时偏移、切换规则、偏移分段（段数与整体生效年份）与备注；可以按是否实行夏令时筛选，也能按名称、显示名或备注搜索
2. 点新建档案填上时区名；偏移在「偏移分段」表里按段登记，每行一段（开始年份、结束年份、这段期间的偏移），点添加一段可以继续往后接；实行夏令时的档案还要把夏令时偏移与开始、结束两段切换规则（第几个星期几的几点几分）填上
3. 点档案行上的详情，可以看到这条时区完整的分段历史，并输入任意年份查它那一年的实际偏移
4. 换算台选好日期、时刻与来源时区，点换算一遍，页面列出每个已登记时区在**输入年份所落分段**下的当地日期、当地时刻、星期、与来源是否同一天、该年偏移、落在分段以及跟来源时区差多少；这一年没有分段覆盖的时区列在最后并标成不可用，给出原因
5. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项或具体的分段那一行上

## 换算口径

- 换算按输入日期的**年份**取偏移：先看来源时区在这一年落在哪一段，把输入的当地时刻减去该段的偏移得到基准时刻，再逐个时区按同一年各自落段的偏移加上去
- 来源时区在输入年份没有任何分段覆盖时，换算直接不成立，接口返回 409 并说明原因（例如早于最早分段、晚于最后一段结束年）
- 某个目标时区在输入年份没有覆盖时，这一条按不可用处理，结果里排在可用时区之后，不给当地时刻，只写明原因
- 每个可用时区的当地日期与时刻都由基准时刻加上该年所落分段的偏移算出，日期是否翻到前一天或后一天按公历日比较
- 与来源时区的时差按两边在同一年所取偏移的差值给，整小时只写小时，带分钟的把分钟也写出来
- 可用结果按偏移从小到大排列，来源时区那一条在页面上会标出来
- 档案里登记了夏令时规则不等于换算时已经计入夏令时，规则本身如何落到具体日期上需要另行处理

## 登记口径

- 时区名称写成地区加城市，例如 `Asia/Shanghai`；基准时可以写 `UTC`；最长 40 个字符，不能重复
- 偏移按**分段**登记：同一条时区可以分成几段（最多 20 段），每段包含开始年份、结束年份与这段期间的偏移（整数分钟，范围 -720 到 840，带半小时或三刻直接写分钟数，例如 330、345）
- 分段按开始年份排序后必须首尾相接：下一段的开始年份必须正好等于上一段结束年份的下一年。两段覆盖到同一年按重叠拒绝，例如一段 2000–2010、下一段从 2008 开始，会指出「在 2008 至 2010 年重叠」；中间有空年按空洞拒绝，例如 2000–2010 后下一段 2013 才开始，会指出「中间 2011 至 2012 年没有任何分段覆盖」
- 结束年份留空表示这一段至今有效；开口段最多一段，而且只能是最后一段，段内结束年份早于开始年份同样会被拒绝
- 档案整体的生效年份取首段开始年与末段结束年，列表与换算默认使用的「当前偏移」取最后一段的偏移；这两个字段由分段表反推，不需要单独填
- 旧档案只有单一偏移与生效年份时仍然兼容，读取时自动整成一段；接口也接受不带 `segments` 的旧写法
- 初始数据里的 `Asia/Kathmandu` 是分段样例：1971–1985 年为 330 分钟，1986 年起为 345 分钟
- 实行夏令时的档案必须填夏令时偏移，且要比当前（最后一段）标准偏移更大（数值上更靠前）
- 切换规则分开始与结束两段，每段写清月份、第几个星期（一到四或者最后一个）、星期几、小时与分钟
- 年份一律填 1900 到 2100 之间
- 备注用来写这条档案需要留意的地方，最长 200 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "zones": [...] }`。每条档案除原有字段外带一个 `segments` 数组，每段为 `{ "fromYear": 1971, "toYear": 1985, "offsetMinutes": 330 }`，`toYear` 为 `null` 表示至今；顶层的 `offsetMinutes`、`fromYear`、`toYear` 由分段表反推（分别取末段偏移、首段开始年、末段结束年）。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据，旧档案（没有 `segments`）读取时自动整成一段。

## 接口一览

| 方法   | 路径             | 说明                                       |
| ------ | ---------------- | ------------------------------------------ |
| GET    | /api/health      | 服务状态检查                               |
| GET    | /api/zones       | 时区档案清单，支持按是否实行夏令时筛选与关键词搜索 |
| POST   | /api/zones       | 新增时区档案                               |
| GET    | /api/zones/:id   | 查看单条档案（含完整分段历史）             |
| GET    | /api/zones/:id/offset?year=1980 | 查这条时区在某一年落在哪段、实际偏移是多少；未覆盖时返回 `available:false` 与原因 |
| PATCH  | /api/zones/:id   | 修改档案（`segments` 整体替换分段表）      |
| DELETE | /api/zones/:id   | 删除档案                                   |
| POST   | /api/convert     | 按输入年份落段把一个时刻换算到所有已登记时区，未覆盖的时区标为不可用 |

新增与修改时分段表通过 `segments` 提交；分段重叠、有空洞、开口段不在最后、段内年份倒置等情况返回对应错误码（`SEGMENT_OVERLAP`、`SEGMENT_GAP`、`SEGMENT_OPEN_NOT_LAST`、`SEGMENT_RANGE_INVALID` 等），`field` 精确到 `segments[第几段].字段`。换算时来源时区在输入年份不可用返回 409（`ZONE_UNAVAILABLE_IN_YEAR`）。

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
