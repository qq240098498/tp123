# tp123 时区与时间换算工作台

一个本地小工具：把各地时区连同分段偏移历史与夏令时规则登记进来，再把某一个时刻换算到所有已登记的时区，页面上直接看出各地是当地的几点、谁的日期已经翻到前一天或者后一天、跟来源时区差了几个小时。有的地区几十年前换过偏移，同一条时区可以按年份分段登记几个偏移区间；时区名写得不合规矩、偏移超出范围、夏令时偏移不比标准偏移靠前、开始与结束两段规则写得一模一样、分段之间发生重叠或留出年份空洞，保存时当场就会指出来，并写清是哪两段撞上、或者哪几年空着。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5123>

端口固定为 `5123`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 时区档案区列出时区名称、显示名称、当前偏移、偏移分段情况、是否实行夏令时、夏令时偏移、切换规则、夏令时生效年份与备注；可以按是否实行夏令时筛选，也能按名称、显示名或备注搜索
2. 点新建档案填上时区名，再在「偏移分段历史」里按年份顺序登记若干段，每段写清开始年份、结束年份与这段期间的偏移；最后一段结束年份留空表示至今，点「再加一段」可以继续往下接；点「详情」可在弹窗里看到这条时区完整的分段历史
3. 实行夏令时的档案还要把夏令时偏移与开始、结束两段切换规则（第几个星期几的几点几分）以及夏令时生效年份填上
4. 换算台选好日期、时刻与来源时区，点换算一遍，页面列出每个已登记时区的当地日期、当地时刻、星期、与来源是否同一天、该年落在哪个分段、实际用的偏移以及跟来源时区差多少；该年没有分段覆盖的时区单独按不可用列出并写清原因
5. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 换算口径

- 换算按输入日期的年份取偏移：先看来源时区的哪一段覆盖这一年，用那一段的偏移把输入当地时刻折成基准时刻，再逐个时区找覆盖这一年的分段、加各自该段的偏移
- 输入年份没有被来源时区的任何分段覆盖时，整个换算不成立并直接说明原因（在最早一段之前、最后一段之后，或某两段之间空着）
- 目标时区在这一年落不进任何分段时不参与时刻计算，按不可用单独列出：是在最早一段之前、最后一段之后，还是哪两段之间的空档，原因直接写在该行
- 每个时区的当地日期与时刻都由基准时刻加上该年所在段的偏移算出，日期是否翻到前一天或后一天按公历日比较
- 与来源时区的时差按两边该年所用偏移的差值给，整小时只写小时，带分钟的把分钟也写出来
- 可用结果按偏移从小到大排列，来源时区那一条在页面上会标出来；不可用行排在清单最后

## 偏移分段的登记口径

- 时区名称写成地区加城市，例如 `Asia/Shanghai`；基准时可以写 `UTC`；最长 40 个字符，不能重复
- 同一条时区的偏移历史分成若干段，每段包含开始年份、结束年份与这段期间的偏移（整数分钟，范围是 -720 到 840，带半小时或三刻的地区直接写对应的分钟数，例如东五区半写 330、加德满都写 345），结束年份留空表示这段至今有效；所有年份都填 1900 到 2100 之间
- 分段按开始年份排序后必须首尾相接：相邻两段，后一段开始年份必须正好是前一段结束年份的下一年；早了就是重叠（当场指出哪两段、撞上的是哪几年），晚了就是空档（指出空着的是哪几年）
- 开放至今（结束年份留空）的分段只能放在最后，否则它与后面的每一段都重叠，保存时同样拒绝
- 一条档案最多登记 20 个分段
- 实行夏令时的档案必须填夏令时偏移，且要比它生效期间每一段标准偏移都更靠前（数值更大）；夏令时的开始与结束年份如果填写，必须落在偏移分段已经覆盖到的年份里，结束年份留空表示至今实行
- 切换规则分开始与结束两段，每段写清月份、第几个星期（一到四或者最后一个）、星期几、小时与分钟，两段不能完全相同
- 备注用来写这条档案需要留意的地方，最长 200 个字符
- 档案里登记了夏令时规则不等于换算时已经计入夏令时，规则本身如何落到具体日期上需要另行处理

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "zones": [...] }`，每条档案的偏移历史放在 `offsetPeriods`（`{ fromYear, toYear, offsetMinutes }` 的数组，按年份首尾相接，最后一段 `toYear` 为 `null` 表示至今）。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。读到旧版本只有单个 `offsetMinutes` 与一对生效年份的档案时，会在载入时自动迁成只有一段的分段历史，夏令时的生效年份迁到 `dstFromYear`/`dstToYear`。

## 接口一览

| 方法   | 路径             | 说明                                       |
| ------ | ---------------- | ------------------------------------------ |
| GET    | /api/health      | 服务状态检查                               |
| GET    | /api/zones       | 时区档案清单，支持按是否实行夏令时筛选与关键词搜索 |
| POST   | /api/zones       | 新增时区档案                               |
| GET    | /api/zones/:id   | 查看单条档案                               |
| PATCH  | /api/zones/:id   | 修改档案                                   |
| DELETE | /api/zones/:id   | 删除档案                                   |
| POST   | /api/convert     | 把一个时刻换算到所有已登记的时区           |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
